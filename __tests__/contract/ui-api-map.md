every UI interaction in `app/(student)/*`, `app/(parent)/*`, `app/(auth)/*`
and the backing Next.js API route.

If a row here changes, the matching test in `api-contract.test.ts` should
change in the same commit. If you add a new screen that calls an API, add
the row here and add a test.

## 3. NextAuth providers actually configured

`lib/auth.ts:570-597` configures **GoogleProvider only**. EmailProvider is
commented out. CredentialsProvider is not present.

Implications locked in by the tests:
- Any UI button that calls `signIn('email', ...)` will silently fail. **AuthScreen no longer renders one.**
- Any UI button that calls `signIn('credentials', ...)` will silently fail. **AuthScreen no longer renders one.**
- `/api/auth/signup` exists and creates a `User` row with bcrypt-hashed password, but it is not wired through NextAuth, so created users cannot sign in. Treat the route as dormant.

## 5. Known missing pieces (NOT fixed in this pass)

After this round, the following Phase-6 journey gaps were all closed by
wiring the NEW UI to existing endpoints (no new API routes created):

- ✅ Under-13 verify flow: `POST /api/auth/parent/verify-otp` now wired
  inline in `/student/onboarding` consent step. `proxy.ts:119` allowlist
  entry for `/student/verify-parent` removed.
- ✅ Parent progress real data: switched from `/api/parent/progress` to
  `/api/parent/dashboard` (subjectProgress topicsCovered/totalTopics +
  readiness) + `/api/parent/schedule` (per-day activity + recent
  sessions).
- ✅ Session completion: NEW `/session/[topicId]/page.tsx` now mounts the
  already-wired `SessionContainer`, which drives `/api/session/start` →
  `/next` → `/practice/submit` → `/test/submit` → completion through
  the existing `useSession` hook.
- ✅ Razorpay upgrade: `/student/upgrade` now calls
  `/api/student/subscription/order` → opens Razorpay checkout (script
  loaded via `next/script`) → calls `/api/student/subscription/verify`
  on success.
- ✅ Diagnostic real questions: `/student/diagnostic` now picks a subject
  from `/api/user/profile.resolvedSubjects` and mounts `DiagnosticFlow`
  in adaptive mode, which talks to `/start` → `/answer` → `/submit`.

Remaining cosmetic items:

- ✅ Auth redirect alignment: `proxy.ts` now redirects all unauthenticated
  protected routes to `/auth/get-started` (the NextAuth `pages.signIn`
  destination) with `callbackUrl` set, and `source=parent` for parent
  routes. The earlier `/login/student` / `/login/parent` / `/auth/signin`
  split was removed.

- ✅ XP / streak / badges on StructuredSession completion: `sessionEngine`
  `persistCompletionProgress` now calls `awardXP` → `updateStreak` →
  `checkSessionBadges`. Results are carried on `SessionCompletedPayload`
  (`badgesAwarded`, `currentStreak`) so the listener can pass real badge
  names to `notifyStudentOnSessionComplete` without re-querying. Each
  step is independently try/caught so a single failure cannot block
  `SESSION_COMPLETED` emission.
