# Spinzy Academy — Data Model Reference

**Last updated: 2026-03-23**

Source of truth: `prisma/schema.prisma` (Prisma 6.19.1, PostgreSQL/Neon).

Model names below are exact — verified against the schema file.

---

## Group 1 — Identity + Auth

**Purpose:** User accounts, OAuth sessions, parent linking, and DPDP consent.
Written by: NextAuth adapter (Account, Session, VerificationToken), onboarding API (User fields), consent flow (Consent).

| Model | Key fields | Notes |
|-------|-----------|-------|
| `User` | id, name, email, phone, role, grade, board, language, accountStatus | Central identity record. `grade`/`board` immutable after first save. |
| `Account` | userId, provider, providerAccountId | NextAuth OAuth account link. |
| `Session` | sessionToken, userId, expires | NextAuth session (do not remove). |
| `VerificationToken` | identifier, token, expires | NextAuth magic link (do not remove). |
| `ParentProfile` | userId | One per parent user — created on role promotion. |
| `ParentStudent` | parentId, studentId, status | Parent ↔ student link. Status: active/pending/revoked. |
| `ParentInvite` | studentId, code, status, expiresAt | Time-limited invite code generated by student, redeemed by parent. |
| `Consent` | userId, scope, givenAt, withdrawnAt | DPDP consent record. Scopes: DATA_PROCESSING, AI_INTERACTION, PARENT_NOTIFICATION, MARKETING. |
| `DeletionRequest` | userId, requestedAt, pseudonymisedAt, purgedAt | DPDP right-to-erasure. One per user. |

## Group 2 — Curriculum Taxonomy

**Purpose:** The structural backbone — boards, grades, subjects, chapters, topics. This data is seeded by `scripts/seed-taxonomy.cjs` and enriched by the HydrateAll pipeline. All writes are upsert-based and idempotent.

| Model | Key fields | Notes |
|-------|-----------|-------|
| `Board` | name, slug, lifecycle | CBSE (`cbse`), ICSE (`icse`). |
| `ClassLevel` | boardId, grade (1–12), slug | Unique on `(boardId, grade)`. |
| `SubjectDef` | classId, name, slug, lifecycle | Unique on `(classId, slug)`. Written by seed-taxonomy.cjs. |
| `ChapterDef` | subjectId, name, slug, order, lifecycle | Written by SyllabusWorker. |
| `TopicDef` | chapterId, name, slug, order, lifecycle | Written by SyllabusWorker. Content gate checks `topicDef.count > 0`. |
| `Concept` | topicId, subjectId, name, irt_b, bloomLevel | IRT difficulty parameter per concept. Used by learning plan engine. |
| `BoardChapterWeight` | chapterId, weightMarks | Board exam mark allocation per chapter. Used by readiness score. |
| `BoardSubjectConfig` | subjectDefId, isCore | Core vs optional subject per board+grade. |

## Group 3 — Content Generation

**Purpose:** Tracks and stores AI-generated curriculum content. Written entirely by the `content-engine-worker` process executing the HydrateAll pipeline.

| Model | Key fields | Notes |
|-------|-----------|-------|
| `HydrationJob` | jobType, board, grade, subject, status, rootJobId, parentJobId | Tracks every syllabus/notes/questions job. Status: pending/running/failed/completed/cancelled. |
| `Outbox` | queue, payload, sentAt, attempts | Transactional outbox — the reconciler reads this and dispatches to BullMQ. |
| `OutboxDeadLetter` | originalOutboxId, deadLetterReason, failedAt | Rows that exceeded MAX_ATTEMPTS. |
| `JobLock` | jobName, lockedUntil | Distributed lock to prevent overlapping scheduler jobs. |
| `ExecutionJob` | jobType, entityType, entityId, status, attempts | Tracks sub-execution within a pipeline run. |
| `JobExecutionLog` | jobId, event, prevStatus, newStatus | Append-only event log per `ExecutionJob`. |
| `AIContentLog` | model, promptType, board, grade, subject, topic, tokensIn, tokensOut, costUsd, success | One row per LLM call during content generation. |
| `TopicNote` | topicId, language, version, status, contentJson | AI-generated study notes per topic. Source for RAG + student reading. |
| `GeneratedTest` | topicId, title, difficulty, language, version, status | AI-generated test per topic. |
| `GeneratedQuestion` | testId, type, question, options, answer, explanation | Individual question rows within a GeneratedTest. Lazily promoted to `Question` on first use. |

## Group 4 — RAG Corpus

**Purpose:** Curriculum text chunks with pgvector embeddings for retrieval-augmented generation during tutor turns.

Written by: `scripts/scrape-ncert.ts` (NCERT content ingestion).

| Model | Key fields | Notes |
|-------|-----------|-------|
| `CurriculumChunk` | conceptIds, content, board, subject, grade, contentHash, embedding (vector 1536) | One chunk per paragraph/section. SHA-256 dedup. pgvector cosine search. |
| `IngestRunLog` | runAt, fileSource, board, subjectId, chunksCreated, embeddingsGenerated | Audit record per scrape run. |

---

## Group 5 — Student Learning State

**Purpose:** Tracks what each student knows, where they are in the curriculum, and their active sessions.

Written by: tutor turn API, session engine, and scheduler (readiness precompute).

| Model | Key fields | Notes |
|-------|-----------|-------|
| `LearningSession` | studentId, activityType, startedAt, completedAt, difficultyLevel | One row per activity a student engages with. |
| `StructuredSession` | studentId, topicId, state (SessionPhase), startedAt, completedAt | V2 session engine record. Phases: OVERVIEW → EXPLANATION → PRACTICE → TEST → HOMEWORK → COMPLETE. |
| `SessionEvent` | sessionId, eventType, timestamp | Audit events within a StructuredSession (SESSION_STARTED, PHASE_STARTED, QUESTION_ANSWERED, etc.). |
| `AITutorTurnLog` | sessionId, callType, model, inputTokens, outputTokens, costUsd, latencyMs, safetyFlagged | One row per LLM call during a tutor session. |
| `StudentConceptState` | studentId, conceptId, masteryScore, theta, stability, retention, nextReviewAt | IRT + spaced-repetition state per student × concept. |
| `LearningPlan` | studentId, subjectId, examDate, weeklyGoal | One plan per student × subject. |
| `LearningPlanItem` | planId, conceptId, weekNumber, orderInWeek, status | Individual concept in a learning plan. |
| `DiagnosticSession` | studentId, subjectId, status (DiagnosticStatus), score | Persists diagnostic test state to DB. Redis-only state was a launch risk (eviction). Unique per student × subject. |
| `ReadinessStatus` | studentId, subject, board, coveragePercent, avgMastery, readinessScore, readinessLabel | Precomputed exam readiness. Labels: not_started / needs_work / on_track / ready. |
| `StudentTopicMastery` | studentId, topicId, masteryLevel, accuracy, questionsAttempted | Topic-level mastery aggregate. |
| `StudentTopicProgress` | studentId, topicId, mastery, practiceCount, lastStudiedAt | Topic progress for the home engine. |

## Group 6 — Assessment

**Purpose:** The question bank, student answers, and doubt resolution system.

| Model | Key fields | Notes |
|-------|-----------|-------|
| `Question` | topicId, board, grade, subject, type, prompt, choices, correctAnswer, status (QuestionStatus), irt_b | Canonical question bank. Promoted from `GeneratedQuestion` by `lib/tests.ts:syncFromGeneratedQuestions()`. |
| `AttemptQuestion` | testResultId, questionId, order, timeSpent, result | One row per question per test attempt. |
| `Answer` | attemptQuestionId, rawAnswer, normalizedAnswer, autoScore | Student's answer to an AttemptQuestion. |
| `TestResult` | testId, studentId, score, startedAt, finishedAt | One test attempt result. |
| `SessionQuestionFlag` | questionId, studentId, reason (FlagReason), status | Student flag on a question. At 3 flags the question is auto-quarantined. |
| `QuestionFlag` | questionId, flagType, severity, autoFlagged, status | Admin/system flag on a `StudentQuestion`. |
| `StudentQuestion` | studentId, type, subject, grade, content, status | Student-submitted doubt questions (text/image). |
| `QuestionAnswer` | questionId, content, contentJson | AI or human answer to a StudentQuestion. |
| `DoubtKb` | studentId, sessionId, conceptId, question, answer, embedding (vector 1536) | Shared doubt knowledge base. Deduped via pgvector similarity before LLM call. |
| `DoubtEscalation` | studentId, sessionId, conceptId, doubtText, aiAttempts | Created when AI fails to resolve the same concept question 3 consecutive times. |

## Group 7 — Engagement

**Purpose:** XP, streaks, challenges, and daily tasks that drive habit formation.

| Model | Key fields | Notes |
|-------|-----------|-------|
| `StudentXP` | studentId, source, amount, sessionId, awardedAt | Individual XP award. Sources: session_correct, streak_bonus, revision_complete. |
| `StudentStreak` | studentId, kind, current, best, lastActive | Streak by kind (e.g. `daily`). `User.currentStreak` and `User.longestStreak` are denormalised copies. |
| `StudentEngagementStats` | studentId, currentStreak, longestStreak, lastActiveDate, totalSessionsCompleted | Denormalised engagement cache updated by scheduler. |
| `Challenge` | key, title, startAt, endAt, rewardPoints | Time-bounded challenge. No badge FK (badges dropped in schema audit). |
| `ChallengeParticipation` | challengeId, userId, status, score, rewardApplied | Student participation in a challenge. Unique per challengeId × userId. |
| `DailyTask` | studentId, date, taskType, title, topicId, status, isRecoveryTask | One personalised task per student per day (generated by daily habit engine). |
| `RecoveryEvent` | studentId, inactiveDays, nudgeType, dailyTaskId | Fired when student is inactive 3/7/14+ days. Types: gentle_nudge / easy_task / fresh_start. |
| `HomeworkAssignment` | studentId, topicId, sessionId, questions, status, dueDate, score | Homework assigned at the end of a StructuredSession. |

## Group 8 — Operations + Safety

**Purpose:** Cost tracking, safety events, quality flags, feature flags, and content lifecycle management.

| Model | Key fields | Notes |
|-------|-----------|-------|
| `AuditLog` | adminId, targetEntity, targetId, action (AdminActionType), previousValue, newValue | All admin actions logged here. |
| `DailyCostMetric` | date, sessions, totalCostUsd, costPerSession | Daily LLM cost rollup. Written by scheduler `costReport` job. |
| `SafetyEvent` | triggerType, sessionId, studentId, severity, inputPreview | Fired on PII detection, jailbreak attempt, unsafe output, or distress signal. |
| `StudentFeatureFlag` | studentId, key, enabled | Per-student feature flags for staged rollout. Compound unique `(studentId, key)`. |
| `RegenerationJob` | suggestionId, targetType, targetId, status, instructionJson | Job to regenerate content from an accepted ContentSuggestion. |
| `ContentSuggestion` | courseId, scope, type, severity, message, status | Rule-derived content improvement suggestion (low completion, high retry, etc.). |
| `SystemMetricSample` | timestamp, overall, dbLatencyMs, redisLatencyMs, jobsPending | Periodic health snapshots for the admin monitoring dashboard. |
| `SystemAlert` | type (AlertType), severity, message, active, firstSeen | Active system alerts: REDIS_DOWN, WORKER_STALE, JOB_STUCK, QUEUE_BACKLOG, etc. |
| `WorkerLifecycle` | type, host, pid, status (WorkerStatus), lastHeartbeatAt | Worker process heartbeat — used by admin workers page. |
| `TelemetrySample` | key, timestamp, value, dimensionHash | Generic bucketed metric for flexible observability. |
